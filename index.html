Arrays

  • الـ array تركيب في اللغة بينظم قائمة من العناصر وليه syntax خاص للوصول لعناصره.
  • هو ordered list of values، الاسم واحد للـ array كلها وكل قيمة ليها index رقمي.
  • array حجمها N الـ index بتاعها من 0 لحد N-1.
  • الوصول: اسم الـ array + الـ index بين أقواس، مثال scores[2] = 94 (القيمة التالتة).
  • القيم اسمها array elements، كلها من نفس النوع (element type) وممكن يكون primitive أو object reference.
  • يعني ينفع array of integers أو characters أو String objects.

Declaring Arrays

int[] scores = new int[10];
  • نوع المتغير int[] (array of integers)، والنوع مبيحددش الحجم لكن كل object ليه حجم معين.
  • الـ reference scores بيشاور على array object جديد بيشيل 10 integers.
  • for-each: مناسب لما نعالج كل العناصر من index 0، لكن مينفعش نستخدمه نغير قيم الـ array.
for (int score : scores)
  System.out.println(score);

الحدوتة 📖

حجزت أرض لعمارة بـ new int[10]، فالأرض اتحجزت لعشر شقق. كلمة int[] بس بتقول "دي عمارة أرقام" لكن مش بتقول عدد الشقق، اللي بيحدد العدد هو new. وعلى الباب في حارس اسمه for-each بيعدي على كل الشقق من الأولى ويقرا اللي فيها، لكنه مش مسموح له يغيّر حاجة جوه الشقق.

Alternate Syntax & Initializer Lists

  • الأقواس ممكن تتحط مع النوع أو مع الاسم، فالاتنين equivalent (والأفضل مع النوع):
double[] prices;
double prices[];
  • Initializer list: بتعمل instantiate وتملا الـ array في خطوة واحدة، القيم بين { } ومفصولة بفواصل.

  • من غير new ومن غير تحديد حجم، والحجم = عدد العناصر في القائمة.
  • الـ initializer list بتتستخدم بس في الـ declaration.
الحدوتة 📖

في طريقتين تجيب بيها عمارة. الأولى تحجز الأرض وتفرش كل شقة لوحدها. والتانية "تسليم مفتاح": {147, 323, 89} وخلاص، العمارة اتبنت واتفرشت في خطوة واحدة من غير new ومن غير ما تقول العدد، لأن الشركة بتعد الأثاث وتعرف الحجم. بس العرض ده بيتقدم وقت الإعلان بس. وعلى فكرة الأقواس [] تقدر تكتبها جنب النوع أو جنب الاسم، لكن جنب النوع أحسن.

Arrays of Objects

String[] words = new String[5];
  • ده بيحجز مكان لـ 5 references، مش بيعمل الـ String objects نفسها، وكلهم null في الأول.
  • كل object لازم يتعمل له instantiate لوحده، و System.out.println(words[0]); دلوقتي هترمي NullPointerException.
  • الـ String ينفع بـ literals: String[] verbs = {"play", "work", "eat", "sleep", "run"};
الحدوتة 📖

حجزت قاعة فيها 5 كراسي لـ 5 ضيوف بـ new String[5]. بس الكراسي فاضية، ولسه محدش جه، وكلها null. لو نديت على الضيف الأول قبل ما يوصل هتطلعلك NullPointerException. لازم تجيب كل ضيف بنفسك وتقعّده على كرسيه (instantiate لكل واحد)، إلا لو عملت قائمة الضيوف جاهزة من الأول.

برنامج: max و min والمجموع

المطلوب: حجم من المستخدم ثم (1) إدخال العناصر (2) أكبر عنصر ومكانه (3) أصغر عنصر ومكانه (4) المجموع والمتوسط.

Method Declaration

  • الـ method بلوك كود (مجموعة statements) بتنفذ مهمة معينة، بنكتبها مرة ونستخدمها كذا مرة (reusability).
  • بتسهل التعديل والـ readability بإضافة أو حذف جزء كود.
  • الـ declaration بيحدد الكود اللي هيتنفذ لما الـ method تتنادى (invoked).
  • لما تتنادى الـ flow بيروح للـ method وينفذ كودها، ولما تخلص يرجع لمكان النداء ويكمل.
  • النداء ممكن يرجّع قيمة أو لأ حسب التعريف.
  • التعريف = method header يليه method body.
int calc(int num1, int num2)
{
  int sum = num1 + num2;
  return sum;
}
  • الـ sum و result بيانات local: بتتعمل كل مرة تتنادى فيها الـ method وبتتمسح لما تخلص.
  • تعبير الـ return لازم يتوافق مع الـ return type.
الحدوتة 📖

أم محمد عملت وصفة محشي ومكتوبة على ورقة. كل ما تعوز تطبخ تناديها من غير ما تكتبها من الأول. ده بالظبط الـ method: كود بتكتبه مرة وتناديه كذا مرة. لما تناديها المطبخ بيتفتح وتنفذ الخطوات، ولما تخلص ترجعلك لمكانك. والحاجات اللي جواها زي sum بتتعمل وقت الطبخ وبتتنضف بعده.

Parameters و return

  • الاسم في الـ declaration = formal parameter، والقيم وقت النداء = actual parameters وبتتنسخ في الـ formal.
  • مثال: ch = calc(25, count); فالـ 25 و count بيتنسخوا في num1 و num2.
  • الـ return type بيحدد نوع القيمة الراجعة، والـ method اللي مبترجعش قيمة return type بتاعها void.
  • الـ return statement: return expression; والـ expression لازم يطابق الـ return type.

مثال زوجي / فردي

public static void main(String args[]) {
  Scanner scan = new Scanner(System.in);
  System.out.print("Enter the number: ");
  int num = scan.nextInt();
  findEvenOdd(num);   // method calling
}
public static void findEvenOdd(int num) {
  if (num % 2 == 0) System.out.println(num + " is even");
  else System.out.println(num + " is odd");
}
الحدوتة 📖

ماكينة القهوة هي أحسن مثال. اسم الزرار هو Method Name، والحاجات اللي بتحطها هي الـ parameters، والكباية اللي بتطلع هي الـ return type. ولو الماكينة بتشتغل من غير ما تطلع حاجة تبقى void. وفرق مهم: الفتحة اللي بتتحط فيها البن اسمها formal، والبن اللي حطيته فعلاً اسمه actual، وبيتنسخ في الفتحة وقت النداء.

Types of Method

Predefined (built-in / standard library)

  • معرّفة جاهزة في مكتبات Java وبنناديها مباشرة، وكودها متخزن في المكتبة.
  • أمثلة: length(), equals(), compareTo(), sqrt()
  • مثال: Math.max(9,7) بترجع 9.

User-defined

  • اللي بيكتبها المبرمج وبتتعدل حسب المطلوب، زي findEvenOdd(int num).

Static vs Public (Instance) Method

  • static: تتنادى من غير ما نعمل object من الكلاس.
  • public (instance): بتتنادى بس من خلال object.
public class Class01 {
  static void myStaticMethod() { ... }
  public void myPublicMethod() { ... }
  public static void main(String[] args) {
    Class01.myStaticMethod();
    Class01 obj1 = new Class01();
    obj1.myPublicMethod();
  }
}
الحدوتة 📖

في حاجات جاهزة من السوبر ماركت زي Math.max(9,7) اسمها Predefined، وفي أكل ماما اللي بتعمله بإيدها وده User-defined. وفي نوعين من الخدمات: static زي ماكينة بيع في الشارع تضغط عليها على طول من غير ما تدخل محل، و public (instance) زي الكافيه، لازم تدخل (تعمل object) الأول وبعدين تطلب.

تمارين Methods

1) rangeGeneration (حدود المدى)

  • method بتاخد lower و upper bound وتطبع الأعداد الصحيحة في المدى، وبرنامج بياخد الرقمين ويستخدمها.
  • الحل: لو x <= y نادي الـ method، غير كده اطبع "Error in Range".
public static void RangeGeneration(int x, int y) {
  for (int i = x; i <= y; i++)
    System.out.print(i + ",");
}

2) حساب f

  • f = ((7+10+13+…+97) − (6+11+16+…+106)) / (1! + 2! + 3!)
  • فكرة الحل: method واحدة sum(start, end, step) بتجمع بخطوة معينة وبنناديها مرتين.
  • تصحيح كود الـ PDF بيستخدم sum(7,22,3)+sum(6,31,5) على sum(13,25,2) وده مش مطابق للمعادلة (جمع بدل طرح وحدود مختلفة).
  • الصح: بسط = sum(7,97,3) - sum(6,106,5) ومقام = 1 + 2 + 6 = 9 (استخدم double عشان القسمة).
public static int sum(int start, int end, int step) {
  int total = 0;
  for (int i = start; i <= end; i += step) total += i;
  return total;
}

3) sumArray

public float sumArray(float[] values) {
  float sum = 0;
  for (int index = 0; index < values.length; index++)
    sum += values[index];
  return sum;
}
الحدوتة 📖

المدرس اداهم تلات واجبات. الأول يعد من x لـ y ولو x أكبر يقول Error in Range. التاني معادلة f اللي فيها جمع وطرح بخطوات، فحسن عمل method واحدة sum(start,end,step) وناداها مرتين بدل ما يكتب loop كل مرة. ولقى إن حل الـ PDF بيجمع بدل ما يطرح فصلحه، والمقام طلع 9. والتالت sumArray بتجمع عناصر array.

Variable Length Parameter Lists

  • لما method تعالج عدد مختلف من القيم في كل نداء (مثلاً average(42,69,37) و average(35,43,93,23,40,21,75)).
  • الـ overloading عيبه محتاج نسخة لكل عدد، والـ array عيبه لازم نبنيها قبل كل نداء، فـ Java بتوفر varargs.
  • الـ parameters بتتحط أوتوماتيك في array جوه الـ method.
public double average(int ... list) {
  double result = 0.0;
  if (list.length != 0) {
    int sum = 0;
    for (int num : list) sum += num;
    result = (double) sum / list.length;
  }
  return result;
}
  • تصحيح السلايد كاتب (double) num / list.length والصح sum (الـ num بره الـ loop مش متعرف).
  • النوع ممكن primitive أو object: printGrades(Grade ... grades).
  • الـ varargs لازم تكون آخر parameter، ومينفعش method فيها مجموعتين varargs.
  • الـ method ممكن تاخد parameters تانية قبلها، والـ constructors كمان تقبل varargs.

أسس كتابة الـ Methods

  • Modularity: اتبع Single Responsibility Principle، يعني method واحدة لمسؤولية واحدة، ولو بقت معقدة قسمها لـ methods أصغر.
  • Input Validation: اتأكد من الـ inputs، شيك على null والقيم الخارج المدى وتعامل معاها بهدوء، بـ conditionals أو بـ throw exceptions.
  • Code Reusability: صمم methods تتستخدم في سياقات مختلفة (generic / parameterized).
  • Error Handling: حدد هتعمل throw exception ولا ترجع error codes ولا تعالج جوه الـ method برسايل مناسبة.
  • Code Readability: كود نظيف، أسماء variables و methods معبرة، تنسيق ثابت، وتعليقات توضح الغرض.
الحدوتة 📖

في مطبخ مطعم محترم، كل طباخ ليه مهمة واحدة (Single Responsibility). وقبل ما يطبخ بيتأكد إن المكونات مش فاسدة أو ناقصة (Validation). والوصفة بتنفع في أكتر من فرع (Reusability). ولو حصل مشكلة بيعرف يتصرف (Error Handling). والوصفة مكتوبة بخط واضح وأسماء مفهومة (Readability).

Guidelines to OO Design

  • Understand the requirements: افهم المتطلبات والأهداف، وحدد الـ functionalities وتفاعلات المستخدم وقيود النظام.
  • Identify objects & responsibilities: حدد الـ objects الرئيسية وسلوك كل واحد والعمليات اللي يحتاجها.
  • Define relationships: associations, aggregations, compositions, generalizations (inheritance) وهي بتحدد تعاون الـ objects.
  • Create class diagrams: بـ UML (classes، relationships، multiplicity) وحسّنها مع تطور التصميم.
  • Consider trade-offs: بين performance, maintainability, scalability، وأثر القرارات على الذاكرة وتعقيد الكود، وحقق توازن.
  • Validate the design: راجعه مع stakeholders وخبراء ومطورين وخد feedback بدري.
  • Document the design: قرارات وأسباب وعناصر رئيسية، مع diagrams وتعليقات.
  • General: الـ OO design عملية iterative، خليه مرن للتغييرات المستقبلية وراجعه باستمرار للحفاظ على كود عالي الجودة وقابل للتوسع والصيانة.

Encapsulation

  • دمج الـ data (Fields) مع الـ procedures (Methods) اللي بتشتغل على الداتا دي.
  • Internal view: تفاصيل الـ variables والـ methods جوه الكلاس.
  • External view: الخدمات اللي بيقدمها الـ object وإزاي بيتعامل مع باقي النظام.
  • من برا الـ object كيان encapsulated بيقدم خدمات محددة، والخدمات دي بتعرّف الـ interface بتاعه.
  • الـ object اللي بيستخدم object تاني اسمه client، وبينادي methods من غير ما يعرف الخدمة اتعملت إزاي.
  • أي تغيير في الـ state (variables) لازم يتم عن طريق methods الـ object نفسه.
  • الـ object المغلّف زي black box: شغله الداخلي مخفي عن الـ client، والـ client بينادي interface methods وهي اللي بتدير الـ instance data.

Method Overriding Rules

  • اسم الـ method في الـ child = اسمها في الـ parent، ونفس الـ parameters.
  • الـ method مش static.
  • الـ access في الـ child مش أكثر تقييداً (ممكن أقل تقييداً)، والترتيب: private < default < protected < public.
  • مثال: private في الـ base و public في الـ derived valid، والعكس (public ثم private) not valid.

أسئلة سريعة

  • نعمل override لـ main؟ لا لأنها static. ونعمل overload لـ main؟ أيوه.
  • الـ overloading بتغيير الـ return type بس؟ False، بيحصل conflict.
  • الكود ParentClass.msg() (default) و ChildClass بيعمله protected ويشتغل؟ أيوه لأن الـ overriding method أقل تقييداً.

public static boolean isPalindrom(String str) {
  int i = 0, j = str.length() - 1;
  while (i <= j) {
    if (str.charAt(i) == str.charAt(j)) { i++; j--; }
    else return false;
  }
  return true;
}

class Cat extends Animal {
  public Cat(String name) { super(name); }
  public void makeSound() { System.out.println(getName() + " meows: Meow! Meow!"); }
}
Animal myDog = new Dog("Buddy");        // polymorphic reference
Animal myCat = new Cat("Whiskers");
Animal genericAnimal = new Animal("Unknown");
myDog.makeSound();   // Buddy barks: Woof! Woof!
myCat.makeSound();   // Whiskers meows: Meow! Meow!
genericAnimal.makeSound();  // Unknown makes a generic animal sound.
Animal[] shelter = { new Dog("Rex"), new Cat("Luna"), new Animal("Creature") };
for (Animal animal : shelter) animal.makeSound();
if (myDog instanceof Dog) {    // downcasting
  Dog actualDog = (Dog) myDog;
  actualDog.fetch();   // Buddy is fetching the ball!
}
  • المثال بيوضح method overriding (dynamic polymorphism) واستخدام super، و array من نوع الـ superclass، والـ downcasting مع instanceof لنداء method خاصة بالـ subclass.
  • تنبيه الـ downcast على object مش من نوع الـ subclass بيرمي ClassCastException وقت التشغيل، عشان كده بنشيك بـ instanceof الأول.
الحدوتة 📖

ملجأ حيوانات فيه كلب وقطة وحيوان مجهول. الكل جاي تحت اسم Animal، ولما نقول makeSound() كل واحد بيرد بصوته: الكلب Woof والقطة Meow والمجهول صوت عام. والكلب لوحده بيعرف fetch، فلو عايز تخليه يجيب الكورة لازم تتأكد بـ instanceof وتعمل cast.

Static Members

  • Java بتدعم methods و variables global بتتنادى من غير object، اسمهم static members وبتتعرف بكلمة static.
  • مفيدة لما نحتاج variable مشترك بين كل instances الكلاس (زي عداد عدد الـ objects).
  • Java بتعمل نسخة واحدة بس من الـ static variable وتتستخدم حتى لو الكلاس عمره ما اتعمل منه object.
  • الوصول بالاسم: ClassName.StaticVarName مثل nCircles = Circle.numCircles;
public class Circle {
  private static int numCircles = 0;   // one per class
  private double x, y, r;              // one per object
  Circle(double x, double y, double r) {
    this.x = x;  this.y = y;  this.r = r;
    numCircles++;
  }
}
Circle circleA = new Circle(10, 12, 20);  // numCircles = 1
Circle circleB = new Circle(5, 3, 10);    // numCircles = 2

الحدوتة 📖

في الشارع في لوحة عداد واحدة بتاعة الشارع كله (numCircles) مش لكل بيت. كل ما حد يبني دايرة جديدة (new Circle) العداد بيزيد، حتى لو لسه محدش بنى. وده الـ static: نسخة واحدة للكلاس، وبتوصلها بـ ClassName.var. أما x و y و r فكل دايرة ليها نسختها الخاصة.

Static Methods

  • بتتنادى من غير object (زي main)، وغالباً بتجمع دوال مكتبة مش معتمدة على data members الكلاس (زي Math).
class Comparator {
  public static int max(int a, int b) { if (a > b) return a; else return b; }
  public static String max(String a, String b) {
    if (a.compareTo(b) > 0) return a; else return b;
  }
}
Comparator.max(a, b);    // directly using ClassName (NO objects)
  • static method: تتنادى من غير object. public (instance) method: بس من خلال object.
  • الـ static method تقدر توصل لـ static data member وتغير قيمته.
  • مينفعش تستخدم non-static data member أو تنادي non-static method مباشرة.
  • الـ this و super مينفعش في static context.
الحدوتة 📖

آلة حاسبة عامة معلقة في الميدان (Math.max)، أي حد يستخدمها من غير ما يعمل object. ده static method. بس هي مبتشوفش الحاجات الخاصة بكل بيت (non-static) ومتعرفش تقول this أو super.

Abstraction

  • إخفاء تفاصيل التنفيذ وإظهار الوظيفة بس للمستخدم، يعني نركز على الـ object بيعمل إيه مش بيعمله إزاي.
  • بتتنفذ عن طريق Abstract classes و Interfaces.
الحدوتة 📖

بتسوق عربية من غير ما تعرف الموتور بيشتغل إزاي. أهم حاجة إنها "تمشي"، مش "إزاي". ده الـ Abstraction: نركز على الـ object بيعمل إيه مش بيعمله إزاي، وبنحققه بالـ Abstract classes والـ Interfaces.

Abstract Classes

  • بتتعرف بـ abstract، ممكن فيها abstract و non-abstract methods، وممكن فيها constructors و static methods و final method.
  • مينفعش تتعمل منها objects، وكلاس conceptual بيدي root مشترك لمجموعة classes.
  • أي كلاس بيعمل extends لها لازم يعمل override لكل abstract methods بتاعتها، وهي ممكن تحتوي 0 أو أكتر.
  • الـ final مينفع يتورث، وأحياناً عايزين الخصائص دايماً تتورث وتتستخدم فنعمل abstract classes.
  • لو الكلاس فيه method abstract واحدة أو أكتر لازم يتعرف abstract (وبيبقى abstract تلقائياً).
  • كلاس معرّف abstract حتى من غير abstract methods برضو ميتعملش منه object.
  • الـ subclass ينفع يتعمل منه object لو عمل override لكل الـ abstract methods، وإلا يبقى هو نفسه abstract.
  • مينفعش نعرّف abstract constructors أو abstract static methods.
abstract class ClassName {
  abstract Type MethodName1();     // no body
  Type Method2() { /* method body */ }
}
public abstract class Shape {
  private String name;
  public Shape() { this.name = "Unknown shape"; }
  public Shape(String name) { this.name = name; }
  public abstract void draw();
  public abstract double getArea();
  public abstract double getPerimeter();
}
public class Rectangle extends Shape {
  private double width, height;
  public Rectangle(double width, double height) {
    super("Rectangle");  this.width = width;  this.height = height;
  }
  public void draw() { System.out.println("Drawing a rectangle..."); }
  public double getArea() { return width * height; }
  public double getPerimeter() { return 2.0 * (width + height); }
}
public class Circle extends Shape {
  private double radius;
  public Circle(double radius) { super("Circle"); this.radius = radius; }
  public void draw() { System.out.println("Drawing a circle..."); }
  public double getArea() { return Math.PI * radius * radius; }
  public double getPerimeter() { return 2.0 * Math.PI * radius; }
}
  • السؤال: Shape s = new Shape(); valid؟ No، illegal لأن Shape abstract.
  • Summary: لو مش عايز الكلاس يتورث اعمله final (للـ classes والـ methods). ولو عايزه يتورث ويتستخدم اعمله abstract (للـ classes والـ methods)، والـ subclasses لازم تنفذ الـ abstract methods وإلا ميتعملش منها objects.
الحدوتة 📖

رسمة مبهمة اسمها Shape: كل شكل لازم يرسم نفسه (draw) ويحسب مساحته ومحيطه، لكن محدش يقدر يعمل "شكل" عام. فأي كلاس يورث منها (زي Circle) لازم يكمل كل الـ abstract methods وإلا يبقى هو كمان abstract. ومينفعش new عليها.

Interface

  • طريقة تانية لتحقيق الـ abstraction، ومينفعش تعمل منها objects، والكلاسات implement الـ interfaces.
  • عند التنفيذ لازم تعمل override لكل methods الـ interface، والـ interface مفيهوش constructor.
  • الـ multiple inheritance ممكن بالـ interfaces لأن الكلاس يقدر يعمل implement لأكتر من interface.
  • الـ scope: public أو package-level (default)، وبتتعرف بكلمة interface، وتعريفها abstract ضمنياً.
  • الأعضاء: constant fields، وabstract و static و default methods، وstatic types (nested interfaces و classes)، ومفيهاش instance أو class variables قابلة للتغيير.
  • زي class لكن: كلمة interface، كل methods من غير body، مفيش instance variables، ومينفعش new Trainable().
  • هي زي contract أو protocol أو role، والكود المكتوب لنوع interface بيشتغل مع أي object بينفذها.
  • Interface يقدر يعمل extends لـ interface تانية وبيرث كل أعضائها: interface InterfaceName2 extends InterfaceName1 { ... }

Data members و Methods

  • كل fields الـ interface implicitly public static final ولازم تتهيأ وقت التعريف، وتتوصل بـ InterfaceName.FIELD (مثل Choices.YES).
  • الـ methods abstract و public افتراضياً، وغياب static و default بيخليها abstract.
  • من Java 8: static methods في الـ interface (وهي public ضمنياً).
  • الـ default method بتدي implementation افتراضي للكلاسات اللي بتنفذ الـ interface، ومش مجبرة تعمل لها override (لكن تقدر).
interface SaySomething {
  default void defaultMsg() { System.out.println("Working..."); }  // Default
  void sayMsg(String msg);                                         // Abstract
}
public class Person implements SaySomething {
  public void sayMsg(String msg) { System.out.println(msg); }
  public static void main(String[] args) {
    Person p = new Person();
    p.defaultMsg();  p.sayMsg("Working hard...");
  }
}
  • الكلاس ممكن ينفذ interface-ين (SaySomething, DoSomething) وكل واحدة فيها default method وabstract method، وممكن نعمل override للـ default.

عقد وظيفة بيقول: "أي حد يشتغل هنا لازم يعرف يعمل كذا". أي كلاس يوقّع (implements) ويلتزم يعمل override لكل بنود العقد. وممكن يوقّع على أكتر من عقد في نفس الوقت، وده حل مشكلة الـ multiple inheritance. والـ Interface مفيهاش constructor ومينفعش new عليها.

  • تطبيق فيه abstract class Shape بـ attributes عامة length و width وmethodين abstract Area و Perimeter، و Square و Rectangle (غير abstract) يورثوا منه.

Identify the problems (Circle و B)

  • الـ constructor: radius = radius; غلط، والصح this.radius = radius;
  • في B: Circle(radius); غلط، والصح super(radius);
  • length = length; والصح this.length = length;
  • getArea() في B بتنادي نفسها (recursion لا نهائي)، والصح super.getArea() * length.
  • كمان radius private في Circle فـ B متقدرش توصل له مباشرة.

Show the output
